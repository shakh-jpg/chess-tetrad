# Этап 4. Аккаунты и синхронизация — как устроено

Облако — бесплатный проект **Supabase** (Postgres + вход + API). Если облако не настроено,
приложение работает как раньше, полностью на устройстве.

## 1. Что хранится в облаке

| Таблица | Что внутри | Кто видит |
|---|---|---|
| `coaches` | тренер: id входа, отображаемое имя | только сам тренер |
| `coach_allowlist` | почты, которым разрешено стать тренером | никто через приложение (только SQL Editor) |
| `students` | ученик: **ник** (без фамилии и почты), какой телефон к нему привязан, когда заходил | тренер — своих; ученик — только себя |
| `student_invites` | одноразовый код: 4 знака открыто + **хеш** остальных 8, срок 7 дней, счётчик ошибок | никто (только внутри функций) |
| `sets` | набор: название, **источник** (книга — ставится автоматически) | тренер — свои; ученик — назначенные ему |
| `set_items` | позиция (FEN), ходы и варианты, оценки ходов; комментарии — только если тренер отметил «мои комментарии» | так же, как набор |
| `assignments` | какой набор какому ученику | тренер — свои; ученик — свои |
| `progress` | ученик × задача: попытки, решено/с ошибкой/не решено, коробка повторения, срок | ученик — свой; тренер — своих учеников |

Чего в облаке **нет**: книг (PDF/EPUB), текста и комментариев из книг, настоящих имён и почт учеников,
аналитики. Тренер может удалить ученика — вместе с ним удаляются его прогресс и назначения.

## 2. Вход

**Тренер** — почта + пароль (или ссылка на почту). Стать тренером может только адрес из `coach_allowlist`
(пользователь вписывает свой адрес одной SQL-командой). Платные провайдеры не нужны.

**Ученик** — без почты:
1. Тренер в приложении: «Аккаунт → Добавить ученика» → вводит ник → видит код вида `K7QM-4MZP-X2HD`.
2. Ученик: «Меню → Аккаунт → Я ученик» → вводит код. Приложение входит **анонимно**
   (Supabase Anonymous Sign-In) и привязывает этот телефон к ученику.
3. Код **одноразовый**, действует **7 дней**, после **5 ошибок** блокируется. Хранится только хеш.
   В коде нет похожих символов (0/O, 1/I/L), кириллические «А, В, Е, К…» приложение исправляет само.

**Смена телефона.** Тренер нажимает «Новый код» у ученика, ученик вводит его на новом телефоне.
Прогресс лежит в облаке и переезжает целиком; **старый телефон теряет доступ** в момент ввода нового кода.
Отдельный PIN не нужен: новый код и так выдаёт только тренер, он одноразовый, короткоживущий
и защищён от перебора (8 секретных символов ≈ 8·10¹¹ вариантов, 5 попыток на код,
10 неудачных попыток в час на устройство).

## 3. Безопасность

- **Row Level Security включена на всех таблицах** — правила проверяет сама база, а не приложение.
  Именно поэтому публичный `anon`/publishable-ключ можно класть в приложение.
- Ключ **service_role (secret) не используется вообще** — его нет ни в приложении, ни в репозитории, ни в GitHub.
- Все функции с повышенными правами (`create_student`, `redeem_invite_code`, …) — `SECURITY DEFINER`
  с пустым `search_path` и проверкой роли внутри. Служебные функции закрыты от вызова через API.
- Права на столбцы сужены: ученик не может переписать привязку телефона или ник; тренер не может
  создать ученика в обход функции (без кода).
- Всё это **проверено тестами** на настоящем Postgres (PGlite): `tests/sql/rls.test.js` — 16 сценариев,
  включая «ученик не видит чужое», «чужой тренер не видит моих учеников», «без входа — ничего».

## 4. Офлайн

- Основное хранилище по-прежнему **IndexedDB на устройстве**. Назначенный набор скачивается и
  становится обычной книгой в библиотеке ученика (её задачи решаются без интернета).
- Результат задачи записывается локально и ставится в **очередь** (в памяти браузера, переживает
  перезапуск). Очередь отправляется при появлении сети, при открытии приложения и по кнопке.
- **Правило конфликтов** (одинаковое в приложении и в базе): побеждает запись, где **больше попыток**;
  при равенстве — где **последняя попытка позже**. Правило не зависит от порядка устройств и
  не теряет прогресс, если ученик решал офлайн.
- Тренерские действия (добавить ученика, назначить набор) требуют интернета.

## 5. «Сон» бесплатного проекта

Бесплатный проект Supabase засыпает примерно через 7 дней без запросов. Workflow
`.github/workflows/keepalive.yml` три раза в неделю вызывает функцию `ping()` (бесплатно,
GitHub Actions). Если в репозитории 60 дней не было коммитов, GitHub сам выключает расписание и
присылает письмо — тогда его включают одной кнопкой на вкладке Actions.

## 6. Файлы

- `src/ui/account.js` — окно «Аккаунт» (ученик / тренер).
