# Как подключить облако (Supabase) — пошагово

Займёт 15–20 минут. Всё бесплатно (тариф Free). Пароли и ключи вводите **только сами**;
никому их не пересылайте. В репозиторий ничего секретного не попадает.

> Нужны две вещи из Supabase: **адрес проекта** и **публичный ключ (Publishable key)**.
> Есть ещё **секретный ключ (Secret / service_role)** — его **никогда** никуда не копируйте.

## Шаг 1. Регистрация
1. Откройте https://supabase.com → кнопка **Start your project** (или **Sign in**).
2. Выберите **Continue with GitHub** и войдите своим аккаунтом `shakh-jpg`. Разрешите доступ.
   Банковская карта не нужна.

## Шаг 2. Создать проект
1. Кнопка **New project**. Организация — та, что создалась сама (Free).
2. **Project name**: `chess-tetrad`.
3. **Database Password**: придумайте длинный пароль, сохраните в своём менеджере паролей.
   Приложению он не нужен; никому его не сообщайте.
4. **Region**: ближе к Казахстану — **Central EU (Frankfurt)** (`eu-central-1`).
5. Тариф **Free** → **Create new project**. Подождите 1–2 минуты, пока проект создаётся.

## Шаг 3. Создать таблицы и правила доступа
1. Слева значок **SQL Editor** → **New query**.
2. Откройте в репозитории файл `supabase/migrations/20261114000001_init.sql`
   (на GitHub: файл → кнопка **Raw** → выделить всё → скопировать).
3. Вставьте в редактор → **Run**. Внизу должно быть `Success. No rows returned`.
   Файл можно запускать повторно — ничего не сломается.
4. Там же, новой командой, разрешите своей почте быть тренером (подставьте **свой** адрес,
   маленькими буквами) → **Run**:
   ```sql
   insert into public.coach_allowlist (email) values ('ваша.почта@example.com') on conflict do nothing;
   ```
5. Проверка: слева **Table Editor** — видны таблицы `coaches`, `students`, `sets`, `set_items`,
   `assignments`, `progress` и др.; у каждой есть пометка, что RLS включена
   (**RLS enabled**, без красного предупреждения «RLS disabled»).

## Шаг 4. Разрешить вход учеников без почты
1. Слева **Authentication** → **Sign In / Providers** (раньше раздел назывался **Providers**).
2. Включите **Allow anonymous sign-ins** → **Save**.
3. Там же убедитесь, что **Email** включён (это вход тренера).
   «Confirm email» можно оставить включённым: после регистрации тренеру придёт письмо.
4. Supabase советует для анонимных входов включить CAPTCHA (Cloudflare Turnstile, бесплатно) —
   это можно сделать позже, при 5–10 учениках встроенного лимита (30 входов в час с одного адреса) хватает.

## Шаг 5. Адреса для входа
1. **Authentication** → **URL Configuration**.
2. **Site URL**: `https://shakh-jpg.github.io/chess-tetrad/`
3. **Redirect URLs** → **Add URL**: `https://shakh-jpg.github.io/chess-tetrad/**`
   (и для проверки на этом ноутбуке: `http://127.0.0.1:5173/**` и `http://127.0.0.1:4173/**`) → **Save**.

## Шаг 6. Адрес проекта и публичный ключ
1. Вверху кнопка **Connect** (или **Project Settings → API Keys**).
2. Скопируйте:
   - **Project URL** — вида `https://xxxxxxxxxxxx.supabase.co`;
   - **Publishable key** — начинается с `sb_publishable_…` (если видите только старые ключи —
     берите **anon public**).
3. **Не копируйте** ключ **Secret** (`sb_secret_…`) и **service_role**.

## Шаг 7. Передать их в GitHub (для сборки сайта)
1. https://github.com/shakh-jpg/chess-tetrad → **Settings** → слева **Secrets and variables** → **Actions**.
2. Вкладка **Variables** (не Secrets) → **New repository variable**:
   - Name: `SUPABASE_URL` — Value: адрес проекта из шага 6;
   - Name: `SUPABASE_ANON_KEY` — Value: Publishable key из шага 6.
   Публичный ключ не секрет (его видит любой, кто откроет сайт), его защищают правила RLS из шага 3.
3. Дальше (этап 4, часть B) разработчик соберёт и выложит новую версию; после этого в меню
   приложения появится кнопка **«Аккаунт»**.

## Шаг 8. Первый вход тренера (после выкладки)
1. Откройте сайт → **Меню → Аккаунт → Я тренер** → почта (из шага 3.4) и пароль → **Зарегистрироваться**.
2. Подтвердите почту по ссылке из письма → снова **Войти**.
3. **Добавить ученика** → ник (например, имя без фамилии) → появится код `XXXX-XXXX-XXXX`.
   Передайте его ученику. Код одноразовый и действует 7 дней.
4. Ученик: **Меню → Аккаунт → Я ученик** → вводит код.
5. Откройте у себя книгу с задачами → **Аккаунт → Назначить набор** → отметьте задачи и ученика.

## Если что-то пошло не так
- «Этот адрес не разрешён для тренера» — повторите шаг 3.4 с тем адресом, которым входите.
- Ученик видит «Не удалось подключиться к облаку» — проверьте шаг 4 (анонимные входы).
- Проект «уснул» (Paused) — в Supabase кнопка **Restore**; автоматический пинг из GitHub
  (`Supabase keep-alive`) три раза в неделю этого не допускает.
- Удалить ученика и все его данные: **Аккаунт → Удалить** у ученика.
- Удалить всё облако целиком: Supabase → **Project Settings → General → Delete project**.

## Обновление: вход учеников по паролю

После этого обновления ученик может придумать логин и пароль и входить на любом устройстве без кода. Почта ученика не нужна.

1. Откройте Supabase → ваш проект → **SQL Editor** → **New query**.
2. Откройте файл `supabase/migrations/20261116000001_student_password.sql` (ссылка на Raw-файл в GitHub появится после публикации), скопируйте весь текст, вставьте и нажмите **Run**. Должно быть «Success. No rows returned». Запускать повторно безопасно.
3. Готово. Сайт обновлять не нужно: новая версия сама увидит новые функции.

Что изменится:
- После входа по коду ученик увидит «Придумайте логин и пароль». Можно пропустить.
- В списке учеников у тренера появится пометка «есть пароль». Сам пароль не видит никто: в облаке хранится только его отпечаток (bcrypt).
- Забыл пароль: тренер нажимает «Новый код», ученик входит по коду и придумывает новый пароль.

## Обновление: онлайн-урок

После этого обновления тренер может вести урок на своей доске, а приглашённые ученики видят её у себя:
ходы, варианты, стрелки, переворот доски. Тренер решает, могут ли ученики двигать фигуры и включать движок.
Кроме того, при назначении набора появится галочка **«Разрешить показ решения»**.

Сайт работает и до обновления: тренер увидит «Онлайн-урок ещё не включён в облаке», а решения в
наборах просто останутся скрытыми до решения задачи.

### Шаг 1. Таблицы и правила (SQL)
1. Supabase → ваш проект → **SQL Editor** → **New query**.
2. Откройте файл `supabase/migrations/20261118000001_live_lessons.sql`, скопируйте весь текст,
   вставьте и нажмите **Run**. Должно быть «Success. No rows returned». Запускать повторно безопасно.

### Шаг 2. Закрыть публичные каналы (Realtime Settings)
Урок идёт по **закрытым** каналам: войти в канал урока могут только тренер этого урока и приглашённые
ученики (это проверяют правила из шага 1). Чтобы закрытые каналы нельзя было обойти, выключите
публичный доступ:
1. В левом меню Supabase откройте **Realtime** → **Settings**
   (если такого пункта нет — **Project Settings** → **Realtime**).
2. Найдите переключатель **Allow public access to channels** (может называться короче:
   **Allow public access**) и **выключите** его.
3. Нажмите **Save**.

Приложение не использует публичные каналы, поэтому ничего не сломается. Остальные настройки
(лимиты сообщений, размер сообщения) не трогайте: бесплатного тарифа хватает.

### Шаг 3. Проверка (5 минут, нужны два устройства)
1. Тренер: **Меню → Начать урок** → отметьте ученика → **Начать урок**. Вверху появится «Урок идёт».
2. Ученик (уже вошедший в «Аккаунт»): в течение минуты появится «Тренер начал урок» →
   **Присоединиться**. Если не появилось — потяните страницу вниз или откройте приложение заново.
3. Тренер делает ход — он появляется у ученика. Кнопка «Тренер и ученики» разрешает ученику ходить.
4. Тренер: **Закончить урок**. У обоих в библиотеке появится книга «Уроки» с ходами урока.

### Что хранится
- В таблице `lessons` — только кто ведёт урок, кого позвал, начало и конец. **Ходы в облаке
  не хранятся**: они идут напрямую через Realtime и сохраняются на устройствах (книга «Уроки»).
- Урок, который забыли закончить, закрывается сам через 12 часов.
- Ученику не отправляются PDF и текст книг: только позиция, ходы, варианты и комментарии,
  которые написал тренер.
